- Profile links in `site.social` are live and are the source of truth for every external profile:
  - LinkedIn is `https://www.linkedin.com/in/raul-cardenas-montoya` (verified to load).
  - Instagram, X and Threads all use `KeepOnSpiking`.
  - Never link Facebook; there is no Facebook account.
- Every external profile (GitHub, X, LinkedIn, Hugging Face, Instagram, Threads) should show "Raul Cardenas Montoya" and link `https://raulcardenasmontoya.me`.

For project cards, edit `src/data/projects.ts`. Add public links only when each repository, case study, or demo is ready to share. The included summaries intentionally avoid performance claims and invented outcomes.

The `/work/` page turns that shared project data into project briefs. Keep its questions framed as active investigations unless evidence is available for a stronger statement; do not convert them into outcome claims during copy edits.

Native CUDA and FPGA results belong in `src/content/native-evidence/` as versioned JSON artifacts. Do not invent benchmark numbers. If no measured capture with hardware, workload, units, source repository, source revision, and capture provenance is available, leave the catalog empty.

NIR lab assets in `public/nir/` and `src/data/nir/` are generated by `crates/neuromorphic-adapter/tests/nir_example.rs`; never hand-edit them. The bundled graph is a hand-authored example, so do not describe it as trained, tuned, or measured. A graph converted from a real `.nir` file needs its own provenance (source checksum, upstream revision, license) and a native conversion step; see the NIR section of `docs/architecture/browser-runtime.md`.

The `/labs/plasticity/` scripted session in `src/data/plasticity/scripted-session.v1.json` is generated by `crates/neuromorphic-adapter/tests/plasticity_session.rs`; never hand-edit it. It is one seed of a tiny synthetic task. Do not describe it as a benchmark, call `limbic-critic` an actor-critic, or say a penalty weakens synapses (neuromod converts eligibility traces into weight changes only when dopamine is positive).

The homepage hero's crate trail comes from `src/data/live-runtime.ts`. When the adapter's crate pins change, update it to match `crates/neuromorphic-adapter/Cargo.toml` and `Cargo.lock`; `npm test` fails until they agree. The hero's first paint is a static drawing of the live topology, not a simulation: keep any copy about it to what the `STATIC · diagram` / `LIVE · Rust/WASM` label says, and keep CUDA and FPGA results on `/evidence/`.

Recorded `corpus-ipc` protocol fixtures for `/protocol/` live in `public/protocol/fixtures/v1/` with an out-of-band SHA-256 `manifest.json`. They are generated from a deterministic adapter replay and labelled as derived, not captured. Regenerate them with the command in `crates/neuromorphic-adapter/README.md` instead of editing bytes by hand, and never present them as hardware or live-service captures.

`public/assets/social-card.png` is the 1200×630 social card (profile photo, name and the brand mark). The mark's only source is `src/brand/mark-source.mjs`; `npm run build:brand` regenerates the SVG and PNG favicons, the Apple touch icon and the social card from it. Do not hand-edit those files; `npm test` fails on drift.

Keep each note to what the architecture docs, the tests or the measurements in this repository show; a claim that needs a number that was not measured here does not belong in a note. The three notes published on 2026-10-25 are trimmed from `docs/architecture/browser-runtime.md` and `crates/neuromorphic-adapter/README.md`.

## Artifacts page and counts

`/artifacts/` lists published Rust crates, Hugging Face datasets (grouped by collection) and merged upstream PRs. `/evidence/` stays reserved for measured CUDA/FPGA captures.

- Every count the site prints (the homepage stat row, About, the project briefs, the meta descriptions) comes from `src/artifacts/counts.ts`, which reads the dated snapshots below. Never type a count into copy; `npm test` scans every template, component, layout, data file and note for one in digits (and the briefs for one in words) and fails when it finds any. Briefs in `src/data/projects.ts` take counts through `{{crates}}`, `{{datasets}}`, `{{factoryDatasets}}`, `{{factoryCollections}}`, `{{cratesAsOf}}` and `{{datasetsAsOf}}` tokens.
- The Hugging Face lists and the owner's collections are fetched from the public API at build time (no token). If the API is unreachable, or `SKIP_HF_FETCH=1`, the page uses `src/data/artifacts/hf-snapshot.json` and says so. Refresh it with `node scripts/build-hf-snapshot.mjs`. A dataset in several collections is listed once, under the newest; datasets in none are listed under "Not in a collection".
- The crates come from `https://crates.io/api/v1/crates?user_id=390342` at build time, with the site's `User-Agent` (crates.io crawler policy). If the API is unreachable, or `SKIP_CRATES_FETCH=1`, the page uses `src/data/artifacts/crates-snapshot.json` and says so. Refresh it with `node scripts/build-crates-snapshot.mjs`. Display groups live in `CRATE_GROUPS` (`src/artifacts/crates-source.mjs`); a crate in no group is listed under "Other". Download totals include CI and mirror traffic, so the page says so and makes no adoption claim.
- The "Also on GitHub" index on `/work/` comes from the GitHub API (`/users/{owner}/repos` for `rmems` and `Limen-Neural`) at build time; `GITHUB_TOKEN` is sent when set, only to raise the rate limit. If the API is unreachable, or `SKIP_GH_FETCH=1`, the page uses `src/data/artifacts/github-snapshot.json` and says so. Refresh it with `node scripts/build-github-snapshot.mjs`. Archived, private, forked and profile repositories, the repositories (or whole accounts) a brief already links, and `EXCLUDED_REPOS` (this site, and the repositories #57 holds back until they have results) are left out automatically. Groups live in `REPO_GROUPS` and caveats in `REPO_NOTES` (`src/artifacts/github-source.mjs`); a repository in no group is listed under "Other". Descriptions are the first sentence of each repository's GitHub About text: fix wording there, not here. Run `npm run build && npm run check:links` (network) before publishing; it checks the links in the built `/work/` page (or, with no `dist/`, what the committed snapshot would render) and fails when a brief link or index line does not answer 200 without a redirect.
- A project brief's "Shipped" line states only what the linked README or published artifact shows. Keep the agoge-forger framing from #57 (SFT taught fence formatting; never "0/16 → 10/16").
- Each dataset shows only the status its own card states. Repos with no data files (card only) and `rmems/agent-honest-stop-episodes` are never listed (`EXCLUDED_DATASETS` in `src/artifacts/hf-source.mjs`).
- `src/data/artifacts/upstream-prs.json` lists only PRs the GitHub API reports as merged, with additions, deletions and changed files. Re-verify before adding one. Never list JuliaRegistries/General registrations as contributions.
- Counts carry their "as of" date; update `verifiedAt` when you re-verify.
