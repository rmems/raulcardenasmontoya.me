# neuromorphic-adapter

The Rust/WASM boundary for the portfolio's V1 interactive runtime. It composes
the exact pinned upstream crate surfaces rather than reimplementing their
signal processing, encoding, SNN dynamics, topology, or protocol rules.

## Reproducible validation

The committed lockfile and `rust-toolchain.toml` are part of the contract.

```text
cargo test --locked
cargo check --target wasm32-unknown-unknown --locked
cargo build --target wasm32-unknown-unknown --release --locked
wasm-bindgen --target web --out-dir pkg target/wasm32-unknown-unknown/release/neuromorphic_adapter.wasm
```

Use `wasm-bindgen-cli 0.2.126`, matching the pinned Rust dependency. `pkg/`
and `target/` are generated locally and intentionally not committed.

## Boundary guarantees

- `WasmAdapter.init(seed, config)` accepts only versioned configs: `[3]`
  (delta-only V3), `[4]` / `[4, mode]` (selectable `axon-encoder` modes),
  `[5]` / `[5, mode]` (kinetic-signals telemetry, below), `[6]` /
  `[6, mode]` (contract 5 with the topology sent once, below), `[7]` /
  `[7, mode]` (contract 6 on the 48-neuron topology, below) and `[8]` /
  `[8, mode]` (contract 6 on the 64-neuron topology, below; the live demo
  uses it). It rejects unknown configuration rather than ignoring it. V3 was
  introduced because seeding LIF weights changed deterministic simulation
  state relative to V2.
- `input(sequence, Float32Array)` requires finite samples and a strictly
  increasing `bigint` sequence.
- Contract 5 (`[5]` / `[5, mode]`) treats each input as one `[x, y,
  pressure]` telemetry packet. `src/kinetic.rs` extracts 16 clamped `[0, 1]`
  features with `kinetic-signals` and hands them to `axon-encoder`; snapshots
  expose them as `encoder_features`. See the `kinetic-signals` section of
  `docs/architecture/browser-runtime.md`.
- `step()` uses a caller-seeded `neuromod::StdRng` and returns copied typed
  arrays plus topology and `corpus-ipc` wire-version provenance.
- Contract 6 (`[6]` / `[6, mode]`) is contract 5 whose per-step state carries
  no topology arrays: `WasmAdapter.topology()` returns the projection once
  (`WasmTopology`, the same `topology_*` getters), `state()` leaves the twelve
  topology arrays empty and keeps `topology_digest`, and input, encoding,
  dynamics and the exported neuron state are byte-identical to contract 5
  (`tests/trace_fixture.rs` replays the contract-5 golden under contract 6).
  The live demo uses it: the projection is 91% of a contract-5 snapshot's
  bytes and never changes.
- Contract 7 (`[7]` / `[7, mode]`, RM-2355) is contract 6 on a larger audited
  `synaptic-wiring` topology: `TopologySpec::V7` is 48 neurons with a fan-out
  of 6 (288 synapses, rewire 0.2, delays 1 to 4, a quarter inhibitory) where
  contracts 3 to 6 keep `TopologySpec::LEGACY` (16 / 64) byte for byte. The
  encoder contract stays 16 channels: channel `c` is the mesh source for every
  neuron `n` with `n % 16 == c`, which is the identity on 16 neurons. The LIF
  bank keeps `lif_bank.rs`'s wiring with its own `ShapingProfile::V7` (a
  stronger tonic drive, lower evoked gain and more dither than the frozen
  legacy profile), because `neuromod`'s global lateral inhibition lands on
  nearly every step of a 48-neuron bank. `tests/fixtures/contract7-seed9-trace.json`
  is its golden; `src/runtime/audited-topology-v7.ts` (generated by
  `tests/audited_topology.rs`) is the projection the browser bridge audits.
  The live demo used it until contract 8 (next).
- Contract 8 (`[8]` / `[8, mode]`, RM-2355) is the same step to 64 neurons:
  `TopologySpec::V8` is 64 neurons with a fan-out of 8 (512 synapses, rewire
  0.2, delays 1 to 4, a quarter inhibitory); contracts 3 to 7 stay frozen.
  The `n % 16` source rule and the 16-channel encoder contract are unchanged,
  so channel 0 drives neurons 0, 16, 32 and 48. With eight synapses per
  neuron the routed current is larger, so the bank needs less drive than
  contract 7's: `ShapingProfile::V8` (tonic 1.8× rheobase, evoked gain 0.03,
  dither 0.6) holds 169 to 445 spikes per 40-step window against the 128 to
  512 band, peaks at 22 of 64 neurons and leaves no neuron silent (the
  contract-7 profile reached 542 against the 512 ceiling).
  `tests/fixtures/contract8-seed9-trace.json` is its golden;
  `src/runtime/audited-topology-v8.ts` (generated by
  `tests/audited_topology.rs`) is the projection the browser bridge audits.
  The live demo uses it.
- `dispose()` makes all later runtime operations fail closed.

## Engine

V1 runs `neuromod`'s LIF bank only (`NeuronModel::Lif`; Izhikevich is a
reserved extension point gated on a contract-version increase). Upstream
`with_dimensions` zero-initializes weights, so `build_network` seeds each
neuron's weights uniformly to `WEIGHT_BUDGET / num_channels`, matching
`neuromod`'s `examples/rstdp_demo.rs` convention. The shipped runtime then
rewires that bank in `src/lif_bank.rs` (`LifBankShaping`): one synapse per
neuron, inhibition kept as inhibition, per-neuron thresholds and background
drive, and a 2-step refractory period, so firing is sparse and desynchronised
(RM-2352). The two rate-setting constants (tonic drive, evoked gain) and the
dither form a `ShapingProfile` chosen per topology size: the legacy profile
of contracts 3 to 6 is frozen, and the 48- and 64-neuron banks of contracts
7 and 8 have their own (RM-2355). See the `neuromod` engine integration section of
`docs/architecture/browser-runtime.md` (ADR-0001).

by the native test, `scripts/verify-neuromorphic-wasm.mjs`, and
`scripts/verify-neuromorphic-browser.mjs`. Never hand-edit expected values;
regenerate it with:

```text
cargo test --locked regenerate_seed9_trace -- --ignored --exact
```

## Recorded protocol fixtures

`src/protocol.rs` backs the `/protocol/` viewer. It is compiled only with the
`protocol` cargo feature (off by default), which the labs package build
enables; the default homepage package keeps only the `corpus-ipc` wire-version
constant. `inspectProtocolFixture` enforces a 64 KiB pre-parse limit and checks an out-of-band SHA-256 over the
exact bytes. It then decodes with
`corpus_ipc::WireEnvelope::<IpcMessage>::decode_json` and runs
`Validate::validate()`. Every failure maps to a stable reason code
(`tests/protocol_ingress.rs`). `corpus-ipc` stays on `default-features = false`.

The wire-v1 envelopes in `public/protocol/fixtures/v1/` and their
`manifest.json` digests come from `corpus-ipc` encoding the first firing tick
of a deterministic replay of `tests/fixtures/kinetic-seed9-trace.json`. They
are derived, not captured. Never hand-edit them; regenerate with:

```text
cargo test --locked --features protocol --test protocol_fixtures regenerate_protocol_fixtures -- --ignored --exact
```

Custom topology payloads are deliberately not accepted here. The later
`synaptic-wiring` integration owns that separate versioned topology contract.

## NIR inspection

`src/nir.rs` is compiled only with the `nir` cargo feature (off by default),
which the labs package build enables; the default homepage package never
contains it. It exports `WasmNirInspection` for `/labs/nir/`, which parses a
versioned `shipoftheseus.nir-graph` envelope with `nir-rs` (`serde` feature
only, never `hdf5`) and returns a read-only projection. The bundled example
(`public/nir/lif-readout-example.v1.json`) and its committed projection
(`src/data/nir/lif-readout-example.v1.inspection.json`) are generated by
`tests/nir_example.rs`. Regenerate both with:

```text
cargo test --locked --features nir --test nir_example regenerate_nir_example -- --ignored --exact
```

See the NIR section of `docs/architecture/browser-runtime.md` for the
envelope rules and the native-only `.nir` conversion path.

## Reward-modulated learning lab

`src/plasticity.rs` is compiled only with the `plasticity` cargo feature (off
by default), which the labs package build enables. It exports
`WasmPlasticityLab` for `/labs/plasticity/`: `limbic-critic`'s `SimpleCritic`
maps reward and penalty to modulators, `plasticity-lab`'s `critic` bridge and
`train_step_with_modulators_and_rng` step a two-neuron `neuromod` network with
them, and `run_eval_with_rng` runs a frozen probe on a copy. `plasticity-lab`
is pinned by git revision because the crates.io release still requires
`neuromod ^0.6`. The scripted-session golden
(`src/data/plasticity/scripted-session.v1.json`) is generated by
`tests/plasticity_session.rs`. Never hand-edit it; regenerate with:

```text
cargo test --locked --features plasticity --test plasticity_session regenerate_plasticity_golden -- --ignored --exact
```

See the lab section of `docs/architecture/browser-runtime.md` for the enabled
mechanisms, non-goals, and determinism rules.
